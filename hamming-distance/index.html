The Hamming distance between two integers is the number of positions at which the corresponding bits are different.

Given two integers x and y, return the Hamming distance between them.

 

Example 1:

Input: x = 1, y = 4
Output: 2
Explanation:
1   (0 0 0 1)
4   (0 1 0 0)
       ↑   ↑
The above arrows point to positions where the corresponding bits are different.

Example 2:

Input: x = 3, y = 1
Output: 1

 

Constraints:

  • 0 <= x, y <= 231 - 1

 

Note: This question is the same as 2220: Minimum Bit Flips to Convert Number.

def hammingDistance(x, y):
    z = x ^ y
    cnt = 0
    while z:
        cnt += z & 1
        z >>= 1
    return cnt
Takeaway
Ditch per‑bit loop; use XOR + built‑in popcount.
XOR then count ones
When you XOR two numbers, each bit becomes 1 only where the original bits differ. So the number of 1s in the XOR result is exactly the Hamming distance. This turns a comparison problem into a simple counting problem.
Why it fits (2) — properties
  • The inputs are non‑negative integers up to 2^31‑1, so they fit in 32 bits.
  • The operation needed is just bitwise XOR and then counting set bits, both efficient.
Spot it (3)
  • You need to count how many bit positions differ between two integers.
  • The only information you have is the binary representation of the numbers.
  • The result is a single integer, not a collection.
How you'd derive it (first principles)
  1. Imagine you write x and y in binary.
  2. You notice that wherever the digits are different, XOR gives 1.
  3. So you think: compute x XOR y, then count the 1s.
  4. Then you realize you can count 1s by repeatedly checking the last bit and shifting right.
Plan (4 steps)
  1. Compute xor = x ^ y
  2. Initialize count = 0
  3. While xor > 0, add xor & 1 to count and shift xor right by 1
  4. Return count

def hamming_distance(x, y):
    xor = x ^ y
    count = 0
    while xor:
        count += xor & 1
        xor >>= 1
    return count
Complexity: O(log max(x, y))

✅ Quick check

Q1: Why does applying XOR to the two numbers give you exactly the positions where their bits differ?
Hint: Think of XOR as a direct detector of mismatched bits.
Because XOR creates a 1 only at spots where the bits were opposite; identical bits become 0, opposite bits become 1.
Q2: What happens if you counted the zeros after XOR instead of the ones?
Hint: The goal is to tally the mismatching positions, not the matching ones.
Your count would be wrong because zeros mark matching bits, not the places you want to measure.

Checklist
