Subarray Sums Divisible by K

Given an integer array nums and an integer k, return the number of non-empty subarrays that have a sum divisible by k.

A subarray is a contiguous part of an array.

 

Example 1:

Input: nums = [4,5,0,-2,-3,1], k = 5
Output: 7
Explanation: There are 7 subarrays with a sum divisible by k = 5:
[4, 5, 0, -2, -3, 1], [5], [5, 0], [5, 0, -2, -3], [0], [0, -2, -3], [-2, -3]

Example 2:

Input: nums = [5], k = 9
Output: 0

 

Constraints:

  • 1 <= nums.length <= 3 * 104
  • -104 <= nums[i] <= 104
  • 2 <= k <= 104

Try every start, extend each end — Subarrays are contiguous, so start anywhere and grow the sum one element at a time.
  • n is up to 3 * 10^4, so about 450 million subarrays.
  • Each longer subarray recomputes sums already built from earlier starts.
Complexity: O(n^2) time, O(1) space
def subarraysDivByK(nums, k):
    count = 0
    n = len(nums)
    for start in range(n):
        total = 0
        for end in range(start, n):
            total += nums[end]
            if total % k == 0:
                count += 1
    return count
Takeaway
Ditch it when n is large and the same sums keep being recomputed.
Running total with remainder memory
Walk through nums once and remember the remainder of the running total after division by k. When the same remainder appears again, the numbers between those two places form a contiguous subarray whose sum is divisible by k, so you count matches instead of trying every subarray.
Why it fits (3) — properties
  • A subarray is the difference between two running totals.
  • Two running totals with the same remainder differ by a multiple of k.
  • Only the remainder matters; Python's % also handles negative numbers safely.
Spot it (3)
  • Count contiguous subarrays whose sum is divisible by k.
  • Many subarrays are possible; n reaches 3 * 10^4, so an O(n^2) search is unattractive.
  • Repeated remainders reveal valid contiguous blocks.
How you'd derive it (first principles)
  1. Imagine writing down the total after each number; a consecutive block is found by comparing two of those totals.
  2. If two totals have the same remainder after division by k, their difference is divisible by k.
  3. So store how often each remainder appeared, count repeats as you go, and remember remainder 0 once before reading anything.
Plan (4 steps)
  1. Set up a counter with remainder 0 seen once.
  2. Loop through nums and update the running total's remainder.
  3. Add how many times that remainder was seen before.
  4. Increment that remainder's count.
Start when stuck: Write the running total and its remainder after each number. · Keep a count of remainders already seen, beginning with 0 seen once.
def count_subarrays(nums, k):
    seen = [0] * k
    seen[0] = 1
    remainder = 0
    answer = 0
    for x in nums:
        remainder = (remainder + x) % k
        answer += seen[remainder]
        seen[remainder] += 1
    return answer
Complexity: O(n) time, O(k) space.

✅ Quick check

Q1: Why does seeing the same remainder twice guarantee that the numbers between those two positions form a subarray whose sum is divisible by k? What would break if we only stored the full sums instead of the remainders?
Hint: Think about what the remainder tells you about how far a sum is from the nearest multiple of k.
Two sums with the same remainder differ by a multiple of k, so their difference (the subarray sum) is divisible by k. If we stored only the full sums we would lose this shortcut and would have to compare every pair again, making the algorithm slow.
Q2: Why do we start with remainder 0 counted once before processing any number? What would we miss if we began with an empty table?
Hint: Consider a subarray that begins at index 0; its sum is just the running total after the first few numbers.
That initial count captures subarrays that start at the first element and whose sum itself is divisible by k. Without it, those subarrays would never be counted.

Checklist

If you need to count contiguous subarrays whose sum is divisible by k, count repeated running-total remainders.
