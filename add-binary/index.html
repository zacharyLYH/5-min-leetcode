Given two binary strings a and b, return their sum as a binary string.

 

Example 1:

Input: a = "11", b = "1"
Output: "100"

Example 2:

Input: a = "1010", b = "1011"
Output: "10101"

 

Constraints:

  • 1 <= a.length, b.length <= 104
  • a and b consist only of '0' or '1' characters.
  • Each string does not contain leading zeros except for the zero itself.

TL;DR — 30s scan

  • The naive way adds digits left-to-right, forcing the computer to rewrite large chunks of text every step, which is slow. The gold way adds digits right-to-left into a list and flips the list at the end, making it fast.
  • When numbers have different lengths, the naive style often gets messy trying to line them up equally, whereas the column method simply treats missing spots as zero and keeps going.

Right‑to‑left digitwise addition — Binary addition works bit by bit with a carry.
  • Repeated prefix string concatenation creates a new string each step → quadratic time.
  • Scanning from the end is fine but building the result by `res = ch + res` repeats work.
Complexity: O(n*n) where n = max(len(a),len(b))
def addBinary(a, b):
    i, j = (len(a) - 1, len(b) - 1)
    carry = 0
    res = []
    while i >= 0 or j >= 0 or carry:
        total = carry
        if i >= 0:
            total += ord(a[i]) - 48
            i -= 1
        if j >= 0:
            total += ord(b[j]) - 48
            j -= 1
        res.append(chr(total % 2 + 48))
        carry = total // 2
    return ''.join(reversed(res))
Takeaway
Ditch front‑string building; accumulate in a list then reverse.
column addition
Imagine you write the two numbers one under the other, aligned to the right. You start adding from the far‑right column, write down the sum’s lowest bit, and carry any extra to the column on the left. Repeating this for every column gives the final binary sum.
Why it fits (4) — properties
  • inputs contain only ‘0’ and ‘1’
  • lengths can differ up to 10⁴
  • the carry is never larger than 1
  • the result may be one digit longer than the longer input
Spot it (3)
  • you need to add two binary strings bit by bit
  • the strings may have different lengths, so you must handle missing bits as zero
  • only a single carry bit can appear at each step
How you'd derive it (first principles)
  1. Picture the numbers stacked; the rightmost digits are the ones you add first.
  2. If the sum of a column is 0 or 1 you write it down and carry 0; if it’s 2 or 3 you write sum‑2 and carry 1.
  3. Move left, repeat until you’ve processed all digits and any leftover carry.
Plan (4 steps)
  1. Set pointers i and j to the last index of a and b.
  2. Initialize carry = 0 and an empty list for result digits.
  3. While i ≥ 0 or j ≥ 0 or carry > 0: add the bits (if any) and carry, store (total % 2) as a digit, update carry = total // 2, move pointers left.
  4. Reverse the digit list and join into the final string.

✅ Quick check

Q1: Why must you examine the rightmost digits first when adding binary numbers, even though reading text normally starts on the left?
Hint: Think of counting: you always count out the single items at hand before adding groups of ten.
Because binary works like place value (ones, twos, fours). You must solve the smallest values first to determine the carry before moving to larger values.
Q2: What special case allows the resulting binary sum to be longer than either of the original strings?
Hint: Consider adding 1 (001) and 4 (100). Their sum is 5, which needs three digits.
A leftover carry remains after the last digit of the longer input is processed.

Checklist

If you need to sum two binary strings column by column with a carry, iterate from the rightmost bits, add bits and carry, store the result bit, and propagate the carry.
