Find the Key of the Numbers

You are given three positive integers num1, num2, and num3.

The key of num1, num2, and num3 is defined as a four-digit number such that:

  • Initially, if any number has less than four digits, it is padded with leading zeros.
  • The ith digit (1 <= i <= 4) of the key is generated by taking the smallest digit among the ith digits of num1, num2, and num3.

Return the key of the three numbers without leading zeros (if any).

 

Example 1:

Input: num1 = 1, num2 = 10, num3 = 1000

Output: 0

Explanation:

On padding, num1 becomes "0001", num2 becomes "0010", and num3 remains "1000".

  • The 1st digit of the key is min(0, 0, 1).
  • The 2nd digit of the key is min(0, 0, 0).
  • The 3rd digit of the key is min(0, 1, 0).
  • The 4th digit of the key is min(1, 0, 0).

Hence, the key is "0000", i.e. 0.

Example 2:

Input: num1 = 987, num2 = 879, num3 = 798

Output: 777

Example 3:

Input: num1 = 1, num2 = 2, num3 = 3

Output: 1

 

Constraints:

  • 1 <= num1, num2, num3 <= 9999

TL;DR — 30s scan

  • The naive version converts each number to a string four times, checks the three numbers together many times, and ends up doing extra work that slows things down.
  • The gold version pads the numbers once, then looks at each digit column one by one and picks the smallest digit in that column; this avoids repeated conversions and runs instantly for any allowed input.

Pad, min each column

Digit-wise min — Each key digit depends only on the i‑th digits of the three numbers, so we can treat positions independently.
  • Repeatedly padding and converting numbers to strings adds overhead.
  • Scanning the same strings four times does redundant work.
Complexity: O(d) where d=4 (constant time)
def keyOfThree(num1, num2, num3):
    a = str(num1).zfill(4)
    b = str(num2).zfill(4)
    c = str(num3).zfill(4)
    res = []
    for i in range(4):
        res.append(str(min(int(a[i]), int(b[i]), int(c[i]))))
    return int(''.join(res))
Takeaway
Replace string padding with direct digit extraction using %10 and //10 to avoid allocations.
Per‑position minimum aggregation
For each of the four digit places, look at the same place in all three numbers (after adding leading zeros), take the smallest digit, and write that down. The four collected digits form the key.
Why it fits (3) — properties
  • Inputs are guaranteed ≤ 9999, so padding to four characters always works.
  • Each column (position) is independent of the others, making per‑column minima a natural step.
  • Resulting key is built directly from those four minima.
Spot it (3)
  • Numbers are limited to four digits → constant‑size loops.
  • The rule “take the smallest digit” applies identically to each column.
  • No cross‑column dependencies appear in the definition.
How you'd derive it (first principles)
  1. Think of the three numbers as strings of length four (add leading zeros).
  2. In every column, compare the three characters and keep the smallest one; that determines the key’s digit for that spot.
  3. Repeating this for all four columns yields the complete key.
Plan (4 steps)
  1. Pad num1, num2, num3 to 4 characters using zfill.
  2. Initialize an empty list mins.
  3. For i in range(4): append min(s[0][i], s[1][i], s[2][i]) to mins.
  4. Form the result as int(''.join(map(str, mins))) and return it.
Start when stuck: Loop through indices 0‑3 representing the four digit places. · At each iteration grab the digit from each padded number, compute their minimum, and store it. · After the loop, combine the four stored minima into a single integer.
def find_key(num1, num2, num3):
    s = [str(num1).zfill(4), str(num2).zfill(4), str(num3).zfill(4)]
    mins = []
    for i in range(4):
        col_min = min(s[0][i], s[1][i], s[2][i])
        mins.append(col_min)
    return int(''.join(map(str, mins)))
Complexity: O(1) time and O(1) extra space – constant four operations.

✅ Quick check

Q1: In the problem, what does taking the minimum digit in each column achieve?
Hint: Imagine changing only one digit while leaving the others unchanged – the key’s digit for that place becomes that new smaller digit.
It builds the key by keeping the smallest digit from the three numbers that share the same place (units, tens, hundreds, thousands).
Q2: Why would the current algorithm need a maximum width of 9999 (or four digits) before you could use the per‑position minimum trick?
Hint: If the numbers were longer, you would have extra positions beyond the fourth digit and the simple min‑per‑column would miss them.
Because the trick relies on having exactly four slots to fill, so each column exists. Without a fixed width you cannot safely assume a fourth slot is present.
