Minimum Difficulty of a Job Schedule

Hard Array, Dynamic Programming
LeetCode →

Problem

Show full problem ↕

You want to schedule a list of jobs in d days. Jobs are dependent (i.e To work on the ith job, you have to finish all the jobs j where 0 <= j < i).

You have to finish at least one task every day. The difficulty of a job schedule is the sum of difficulties of each day of the d days. The difficulty of a day is the maximum difficulty of a job done on that day.

You are given an integer array jobDifficulty and an integer d. The difficulty of the ith job is jobDifficulty[i].

Return the minimum difficulty of a job schedule. If you cannot find a schedule for the jobs return -1.

 

Example 1:

Input: jobDifficulty = [6,5,4,3,2,1], d = 2
Output: 7
Explanation: First day you can finish the first 5 jobs, total difficulty = 6.
Second day you can finish the last job, total difficulty = 1.
The difficulty of the schedule = 6 + 1 = 7

Example 2:

Input: jobDifficulty = [9,9,9], d = 4
Output: -1
Explanation: If you finish a job per day you will still have a free day. you cannot find a schedule for the given jobs.

Example 3:

Input: jobDifficulty = [1,1,1], d = 3
Output: 3
Explanation: The schedule is one job per day. total difficulty will be 3.

 

Constraints:

  • 1 <= jobDifficulty.length <= 300
  • 0 <= jobDifficulty[i] <= 1000
  • 1 <= d <= 10

  • Gold builds a table so each sub‑problem (first i jobs in k days) is solved once and then looked up instantly.

contiguous partition DP — Jobs stay ordered, so each day is a nonempty contiguous block; choose d-1 cut points.
  • Cut patterns: C(n-1,d-1), exponential.
  • Same (i, day) repeats across different cut histories.
Complexity: Naive O(n*C(n-1,d-1)) time; memoized O(d*n*n) time, O(n*n) space here.
from functools import cache
from itertools import accumulate

def minDifficulty(jobDifficulty, d):
    n = len(jobDifficulty)
    mx = [list(accumulate(jobDifficulty[i:], max)) for i in range(n)]

    @cache
    def dp(i, day):
        return mx[i][n - i - 1] if day == d - 1 else min((mx[i][j - i] + dp(j + 1, day + 1) for j in range(i, n - (d - day - 1))))
    return -1 if n < d else dp(0, 0)
Takeaway
Use cut-point DP for ordered jobs; ditch raw recursion once n is more than tiny.
Partition DP
Treat the job list as one long sequence that must be divided into d consecutive groups. The cost of a group is simply the hardest job in it. The goal is to find the split points that make the sum of these group-hardnesses as small as possible.
Why it fits (3) — properties
  • Jobs are ordered linearly, meaning any schedule corresponds to cutting the list into d contiguous pieces.
  • The cost of a piece depends only on the maximum difficulty inside it, not the individual jobs.
  • We need exactly d pieces, requiring n >= d jobs otherwise a schedule is impossible.
Spot it (3)
  • Split an array into k subarrays minimizing the sum of subarray maximums
  • Tasks with strict sequential ordering (no crossing allowed)
  • A fixed limit on the number of groups (d)
How you'd derive it (first principles)
  1. Visualize the schedule as placing d-1 dividers between jobs to separate day 1 from day 2, etc.
  2. Define dp[i][k] as the minimal difficulty to schedule the first i jobs in k days.
  3. To compute dp[i][k], imagine the last day ends at job i-1; the last segment runs from some previous job j to i-1. Its cost is the max difficulty in that range plus the optimal cost up to j for k-1 days.
Plan (6 steps)
  1. Create a table `dp` of size (n+1) x (d+1) filled with infinity.
  2. Fill the first row/column: `dp[i][1]` is the max difficulty of the first i jobs.
  3. Loop over day count k from 2 to d.
  4. Loop over the end index i of the schedule.
  5. Loop backward from i to find the best start j for the current day's segment, maintaining a running max to avoid redundant calculations.
  6. Take the minimum of existing `dp[i][k]` and `dp[j][k-1] + current_max`.
Start when stuck: Initialize a DP table where rows represent job counts and columns represent day counts. · Populate the first column (1 day) since that requires taking all jobs up to that point. · Iterate through days (from 2 to d) and update the table by considering every possible end position and start position for the current day.
def min_difficulty(jobDifficulty, d):
    n = len(jobDifficulty)
    dp = [[float('inf')] * (d + 1) for _ in range(n + 1)]
    cur = 0
    for i in range(1, n + 1):
        cur = max(cur, jobDifficulty[i - 1])
        dp[i][1] = cur
    for k in range(2, d + 1):
        for i in range(k, n + 1):
            mx = 0
            for j in range(i - 1, k - 2, -1):
                mx = max(mx, jobDifficulty[j])
            dp[i][k] = min(dp[i][k], dp[j][k - 1] + mx)
    res = dp[n][d]
    return int(res) if res != float('inf') else -1
Complexity: O(n^2 * d)

✅ Quick check

Q1: Why can we compute the best schedule for the first i jobs in k days by only looking at the last day's segment?
Hint: Imagine removing the last day and ask what remains.
Because any optimal schedule must end with some segment; the cost before that segment is already the optimal cost for the first j jobs in k-1 days, which we have stored.
Q2: What would go wrong if we were allowed to reorder the jobs before assigning them to days?
Hint: Think about needing to pick the hardest jobs regardless of where they sit in the list.
The DP that relies on contiguous blocks would no longer be correct, since the hardest job in a day could come from anywhere and we could not just take the maximum of a simple range.

Checklist

If n < d return -1; otherwise fill DP table computing optimal partition sums across contiguous job groups.
