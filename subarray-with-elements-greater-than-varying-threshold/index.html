Subarray With Elements Greater Than Varying Threshold

You are given an integer array nums and an integer threshold.

Find any subarray of nums of length k such that every element in the subarray is greater than threshold / k.

Return the size of any such subarray. If there is no such subarray, return -1.

A subarray is a contiguous non-empty sequence of elements within an array.

 

Example 1:

Input: nums = [1,3,4,3,1], threshold = 6
Output: 3
Explanation: The subarray [3,4,3] has a size of 3, and every element is greater than 6 / 3 = 2.
Note that this is the only valid subarray.

Example 2:

Input: nums = [6,5,6,5,8], threshold = 7
Output: 1
Explanation: The subarray [8] has a size of 1, and 8 > 7 / 1 = 7. So 1 is returned.
Note that the subarray [6,5] has a size of 2, and every element is greater than 7 / 2 = 3.5. 
Similarly, the subarrays [6,5,6], [6,5,6,5], [6,5,6,5,8] also satisfy the given conditions.
Therefore, 2, 3, 4, or 5 may also be returned.

 

Constraints:

  • 1 <= nums.length <= 105
  • 1 <= nums[i], threshold <= 109

def naive(nums, threshold):
    n = len(nums)
    for k in range(1, n + 1):
        for i in range(n - k + 1):
            valid = True
            for j in range(i, i + k):
                if nums[j] <= threshold / k:
                    valid = False
                    break
            if valid:
                return k
    return -1
Takeaway
Only viable for tiny inputs; for large n use monotonic stack or union-find
Monotonic Deque (sliding minimum)
We turn the “all elements > threshold/k” requirement into a simple integer test: nums[i] * k > threshold. While scanning the array we keep a running count of how many elements in the current window of size k already pass the test. Whenever that count equals k we have found a valid subarray.
Why it fits (3) — properties
  • Fixed window size k makes the problem uniform; the condition can be written without fractions.
  • Multiplying both sides by k yields an integer comparison, avoiding floating‑point errors.
  • A monotone deque maintains the smallest element of the window in O(1) per step, allowing quick validation.
Spot it (3)
  • Fixed window size k turns the problem into “does every element in a length‑k block satisfy …?”
  • Rewriting the inequality as element * k > threshold keeps everything integral.
  • A sliding window combined with a monotonically increasing deque gives O(1) min queries, perfect for checking each window in constant time.
How you'd derive it (first principles)
  1. Picture walking along the array while holding a window of exactly k items.
  2. Every time a new item enters, discard any larger items behind it from the back of a deque so the front always holds the smallest value in the window.
  3. Then you simply ask: is that smallest value bigger than threshold/k? If yes, you’re done.
Plan (5 steps)
  1. Initialise an empty deque and a counter `cnt = 0`.
  2. For each index i with value v, add v to the window: if `v*k > threshold` increment `cnt`.
  3. When i reaches k‑1 the first full window appears; if `cnt == k` return k.
  4. Update the window: if the element leaving the window (`nums[i‑k]`) satisfied the condition, decrement `cnt`.
  5. Repeat until the end; if `cnt` never hits k, return -1.

Q1: Why is multiplying the number by the window size better than dividing it for the condition check?
Hint: Remember that combining pieces together (adding/multiplying) is safer than breaking things apart (dividing).
Division creates decimal points that computers struggle with precisely. Multiplying keeps the math exact using whole numbers, avoiding errors.

Hint: Imagine marking items as OK or not; stop the process the moment the count matches the window size.
It acts like a progress bar that tells you exactly when the whole window has been verified, so you don't waste time on bad areas.
