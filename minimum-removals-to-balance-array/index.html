Minimum Removals to Balance Array

You are given an integer array nums and an integer k.

An array is considered balanced if the value of its maximum element is at most k times the minimum element.

You may remove any number of elements from nums​​​​​​​ without making it empty.

Return the minimum number of elements to remove so that the remaining array is balanced.

Note: An array of size 1 is considered balanced as its maximum and minimum are equal, and the condition always holds true.

 

Example 1:

Input: nums = [2,1,5], k = 2

Output: 1

Explanation:

  • Remove nums[2] = 5 to get nums = [2, 1].
  • Now max = 2, min = 1 and max <= min * k as 2 <= 1 * 2. Thus, the answer is 1.

Example 2:

Input: nums = [1,6,2,9], k = 3

Output: 2

Explanation:

  • Remove nums[0] = 1 and nums[3] = 9 to get nums = [6, 2].
  • Now max = 6, min = 2 and max <= min * k as 6 <= 2 * 3. Thus, the answer is 2.

Example 3:

Input: nums = [4,6], k = 2

Output: 0

Explanation:

  • Since nums is already balanced as 6 <= 4 * 2, no elements need to be removed.

 

Constraints:

  • 1 <= nums.length <= 105
  • 1 <= nums[i] <= 109
  • 1 <= k <= 105

TL;DR — 30s scan

  • Naive: sort, then start from each left value and scan forward; it rechecks the same right-side numbers many times.
  • Gold: sort, then keep one moving block; move the right edge forward, and when the block is too big, move the left edge forward until it fits.
  • Switch when: the array is sorted and the right edge only moves forward; then a left value that is too small will never become useful again.
Spot next time: If you can remove any items and the only check is between the smallest and largest kept values, sort the values and look for the longest stretch that stays inside the rule.

Sort + linear scan per element — Sorted array means min and max of any subset are its endpoints; fix left, expand right.
  • n up to 1e5 makes O(n^2) too slow
  • Each start re-scans same range, redundant work
Complexity: O(n^2) time, O(1) space
def min_removals(nums, k):
    nums.sort()
    n = len(nums)
    best = 0
    for i in range(n):
        j = i
        while j < n and nums[j] <= k * nums[i]:
            j += 1
        best = max(best, j - i)
    return n - best
Takeaway
After sorting, use two pointers to find longest valid window in O(n).
sort + sliding window
Sort the values. Then a balanced remaining set only cares about its smallest and largest; if those two fit, every value between them also fits. So you can slide a window over the sorted list and keep the longest window that satisfies max <= min * k.
Why it fits (3) — properties
  • Removing any elements means original order is irrelevant, only values matter.
  • Condition depends only on max and min, not positions.
  • After sorting, if min and max fit, all values between them also fit.
Spot it (3)
  • You may remove any elements and only max/min matter, so order can be ignored.
  • Balanced means max <= min * k, a fixed ratio between two extremes.
  • n up to 1e5, so sort once and scan instead of checking all pairs.
How you'd derive it (first principles)
  1. Imagine you can delete any elements, so original positions do not matter; only kept values matter. So you sort the values from small to large. Then you realize: if nums[i] is the minimum and nums[j] is the maximum, every value between i and j is also safe, so the problem becomes finding the longest safe block.
Plan (5 steps)
  1. Sort nums.
  2. Use left and right pointers over sorted nums.
  3. For each right, move left rightward while nums[right] > nums[left] * k.
  4. Keep the longest valid window length.
  5. Return total length minus longest.
Start when stuck: Sort nums. · Use right as max, shrink left until max <= min * k.

✅ Quick check

Q1: Why does being allowed to remove any items let us sort the numbers first? What breaks if the kept numbers had to stay in their original order?
Hint: What does deleting any items do to the need to remember where each number was?
Removing any items means the kept group is just a group of values, so sorting only reorders values we may keep. If order had to stay, a sorted stretch might not be a legal kept group, and the ends of a sorted stretch might not be the smallest/largest in the original kept order.
Q2: Why can the left edge only move forward as the right edge moves forward? What would make this fail?
Hint: What happens to the block's biggest value when the right edge moves right?
In sorted order, moving the right edge forward can only keep the biggest value the same or make it bigger. If the left edge is too small now, it will not become good later, so we can drop it. This fails if the right edge could move left or if bigger right values somehow made the rule easier.

Checklist

If you can remove elements and validity only depends on the smallest and largest remaining values, sort the array and slide a window until the largest is at most k times the smallest.
