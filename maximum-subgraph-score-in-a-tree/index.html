Maximum Subgraph Score in a Tree

Hard Array, Dynamic Programming, Tree, Depth-First Search

Problem

Show full problem ↕

You are given an undirected tree with n nodes, numbered from 0 to n - 1. It is represented by a 2D integer array edges​​​​​​​ of length n - 1, where edges[i] = [ai, bi] indicates that there is an edge between nodes ai and bi in the tree.

You are also given an integer array good of length n, where good[i] is 1 if the ith node is good, and 0 if it is bad.

Define the score of a subgraph as the number of good nodes minus the number of bad nodes in that subgraph.

For each node i, find the maximum possible score among all connected subgraphs that contain node i.

Return an array of n integers where the ith element is the maximum score for node i.

A subgraph is a graph whose vertices and edges are subsets of the original graph.

A connected subgraph is a subgraph in which every pair of its vertices is reachable from one another using only its edges.

 

Example 1:

Input: n = 3, edges = [[0,1],[1,2]], good = [1,0,1]

Output: [1,1,1]

Explanation:

  • Green nodes are good and red nodes are bad.
  • For each node, the best connected subgraph containing it is the whole tree, which has 2 good nodes and 1 bad node, resulting in a score of 1.
  • Other connected subgraphs containing a node may have the same score.

Example 2:

Input: n = 5, edges = [[1,0],[1,2],[1,3],[3,4]], good = [0,1,0,1,1]

Output: [2,3,2,3,3]

Explanation:

  • Node 0: The best connected subgraph consists of nodes 0, 1, 3, 4, which has 3 good nodes and 1 bad node, resulting in a score of 3 - 1 = 2.
  • Nodes 1, 3, and 4: The best connected subgraph consists of nodes 1, 3, 4, which has 3 good nodes, resulting in a score of 3.
  • Node 2: The best connected subgraph consists of nodes 1, 2, 3, 4, which has 3 good nodes and 1 bad node, resulting in a score of 3 - 1 = 2.

Example 3:

Input: n = 2, edges = [[0,1]], good = [0,0]

Output: [-1,-1]

Explanation:

For each node, including the other node only adds another bad node, so the best score for both nodes is -1.

 

Constraints:

  • 2 <= n <= 105
  • edges.length == n - 1
  • edges[i] = [ai, bi]
  • 0 <= ai, bi < n
  • good.length == n
  • 0 <= good[i] <= 1
  • The input is generated such that edges represents a valid tree.

Takeaway

Tree DP with Rerooting (In-Out DP)
We need the maximum score connected subgraph containing each node. The score sums +1 for good nodes and -1 for bad ones. For a fixed node, we can imagine it as the root: for each neighbor, we can either include the best connected subgraph that contains that neighbor and lies entirely on that side, but only if that best sum is positive. This gives an optimal substructure. To get answers for all nodes, we first compute the best sum in each subtree when the tree is rooted arbitrarily, then we propagate the best sum from the parent side down to children so every node knows the contributions from all directions.
Why it fits (4) — properties
  • The tree has no cycles, so branches from a node are independent.
  • The score is additive, and the decision for each branch is a simple take-it-or-leave-it based on whether its best contribution is positive.
  • The best contribution from a branch depends only on that branch's subtree, which allows a recursive DP.
  • Rerooting lets us reuse the subtree results to compute the parent-side contribution without recomputing from scratch.
Spot it (4)
  • The problem asks for an answer for every node.
  • The graph is a tree.
  • The objective can be broken into independent contributions from each neighbor.
  • We see the pattern of adding max(0, child_value) in a tree DP.
How you'd derive it (first principles)
  1. Start by focusing on one node and ask: what is the best connected subgraph containing it?
  2. You realize you can treat each neighbor separately: for each neighbor, you can either take the whole branch or not.
  3. The best you can get from a neighbor's direction is the maximum sum of a connected subgraph that contains that neighbor and stays on that side. If that best is positive, you add it; otherwise you skip it.
  4. So you need to know, for each directed edge (u -> v), the best sum containing u in the component that does not contain v.
  5. You see that if you root the tree arbitrarily, you can compute the best sum in each subtree easily (downward).
  6. Then you notice that to get the best sum from the parent side, you can subtract your own contribution from the parent's total. This leads to a two-pass approach: one bottom-up to compute subtree values, and one top-down to push the parent-side values to children.
Plan (4 steps)
  1. Build adjacency list and convert good array to weights (+1 for good, -1 for bad).
  2. First DFS (postorder): compute down[u] = weight[u] + sum_{child v} max(0, down[v]).
  3. Second DFS (preorder): for the root, answer is down[0]. For each child v of u, compute the contribution from u's side as up_val[v] = weight[u] + max(0, up_val[u]) + sum_{other children w} max(0, down[w]). Then answer for v is weight[v] + max(0, up_val[v]) + sum_{children of v} max(0, down[child]).
  4. Propagate up_val to children and compute answers.
Start when stuck: Pick an arbitrary root, say node 0. · Do a DFS to compute for each node the best sum of a connected subgraph that contains it and stays within its subtree (call it down). · Then do a second DFS where you pass to each child the best sum from the parent's side (excluding the child's branch). Use that to compute the answer for the child.
def solve(n, edges, good):
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    weight = [1 if g == 1 else -1 for g in good]
    down = [0] * n
    parent = [-1] * n
    children = [[] for _ in range(n)]
    stack = [(0, -1)]
    order = []
    while stack:
        u, p = stack.pop()
        parent[u] = p
        order.append(u)
        for v in adj[u]:
            if v != p:
                children[u].append(v)
                stack.append((v, u))
    for u in reversed(order):
        down[u] = weight[u]
        for v in children[u]:
            if down[v] > 0:
                down[u] += down[v]
    ans = [0] * n
    up_val = [0] * n
    ans[0] = down[0]
    stack = [0]
    while stack:
        u = stack.pop()
        pos_sum = 0
        for v in children[u]:
            if down[v] > 0:
                pos_sum += down[v]
        for v in children[u]:
            up_val[v] = weight[u] + (up_val[u] if up_val[u] > 0 else 0) + pos_sum - (down[v] if down[v] > 0 else 0)
            ans[v] = weight[v] + (up_val[v] if up_val[v] > 0 else 0)
            for w in children[v]:
                if down[w] > 0:
                    ans[v] += down[w]
            stack.append(v)
    return ans
Complexity: O(n) time and O(n) space, where n is the number of nodes.

✅ Quick check

Q1: Why can we treat each neighbor's branch independently in a tree? What would break if the graph had a cycle?
Hint: Think about how many paths connect any two nodes in a tree compared to a graph with a cycle.
In a tree, there is only one path between any two nodes, so the part of the graph on one side of a node does not overlap with the other side. This lets us add their contributions without double counting. If there were a cycle, two branches could share nodes, so we couldn't simply add them because the same node might be counted twice.
Q2: In the two-pass method, why do we need to subtract the child's contribution when computing the parent-side value for that child? What would happen if we didn't subtract it?
Hint: Consider what the parent's total represents and what we want to give to the child. What would happen if we included the child's branch twice?
The parent's total includes the child's branch, but when we want to pass the parent's side value to the child, we must exclude the child's own branch to avoid including it twice. If we didn't subtract, the child would get a value that includes its own branch again, leading to an incorrect, inflated sum.

Checklist

If you need the maximum connected sum containing each node in a tree, compute the best contribution from each neighbor independently and combine them using a two-pass DP (bottom-up then top-down).
