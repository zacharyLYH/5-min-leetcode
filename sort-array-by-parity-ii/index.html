Given an array of integers nums, half of the integers in nums are odd, and the other half are even.

Sort the array so that whenever nums[i] is odd, i is odd, and whenever nums[i] is even, i is even.

Return any answer array that satisfies this condition.

 

Example 1:

Input: nums = [4,2,5,7]
Output: [4,5,2,7]
Explanation: [4,7,2,5], [2,5,4,7], [2,7,4,5] would also have been accepted.

Example 2:

Input: nums = [2,3]
Output: [2,3]

 

Constraints:

  • 2 <= nums.length <= 2 * 104
  • nums.length is even.
  • Half of the integers in nums are even.
  • 0 <= nums[i] <= 1000

Swap each odd position with the next even number using nested loops — It directly applies the parity rule with a straightforward check
  • For n up to 20 000 the inner scan can cause quadratic behavior
  • Repeated forward searches waste work across indices
Complexity: O(n²) worst case, O(n) achievable with a two‑pointer pass
def sort_by_parity(nums):
    even_idx = 0
    for i in range(0, len(nums), 2):
        while nums[i] % 2:
            j = i + 1
            while j < len(nums) and nums[j] % 2 == 0:
                j += 1
            nums[i], nums[j] = (nums[j], nums[i])
    return nums
Takeaway
Two‑pointer sweep gives O(n) time, avoiding the naïve O(n²) approach
Two-pointer swap
You walk through the array with two pointers, one for even indices and one for odd indices. Whenever you find a number in the wrong place you swap it with a mismatched number on the other parity, fixing both spots at once.
Why it fits (3) — properties
  • array length is even
  • exactly half the numbers are even and half are odd
  • we need evens at even indices and odds at odd indices
Spot it (3)
  • the array length is even
  • there are the same number of evens as odds
  • each parity must occupy a specific index parity
How you'd derive it (first principles)
  1. Imagine you scan from the start and see an even number sitting on an odd slot – it’s wrong.
  2. You know there must be an odd number somewhere on an even slot because the totals match.
  3. So you keep two scanners, one on even slots, one on odd slots, and swap whenever both point to wrong numbers.
Plan (4 steps)
  1. loop while i < n and j < n
  2. if nums[i] is even, move i forward by 2
  3. else if nums[j] is odd, move j forward by 2
  4. else swap nums[i] and nums[j], then move both i and j forward by 2
Start when stuck: set i = 0 (first even index) and j = 1 (first odd index) · while both pointers are inside the array, look at what they hold
i = 0
j = 1
n = len(nums)
while i < n and j < n:
    if nums[i] % 2 == 0:
        i += 2
    elif nums[j] % 2 == 1:
        j += 2
    else:
        nums[i], nums[j] = (nums[j], nums[i])
        i += 2
        j += 2
Complexity: O(n)

✅ Quick check

Q1: Why does having exactly half evens and half odds guarantee that the two moving spots will always find a swap when both point to wrong numbers?
Hint: Think about what would happen if there were more evens than odds.
Because every misplaced even on an odd spot forces a misplaced odd on an even spot somewhere else, so the two spots will eventually meet.
Q2: What would go wrong if the array length were odd or the counts of evens and odds were not equal?
Hint: Consider the case where there is an extra even number; where could it go?
The two moving spots could run out of room before fixing all spots, leaving some numbers in the wrong places.

Checklist

If you must place evens on even spots and odds on odd spots with equal counts, use two pointers stepping by 2 and swap mismatches.
