Sort Colors

You are given an array nums with n objects colored red, white, or blue, sort them in-place so that objects of the same color are adjacent, with the colors in the order red, white, and blue.

We will use the integers 0, 1, and 2 to represent the color red, white, and blue, respectively.

You must solve this problem without using the library's sort function.

 

Example 1:

Input: nums = [2,0,2,1,1,0]

Output: [0,0,1,1,2,2]

Explanation:

The array has two 0s, two 1s, and two 2s. Sorting them in-place places all 0s first, then all 1s, then all 2s.

Example 2:

Input: nums = [2,0,1]

Output: [0,1,2]

Explanation:

The array has one each of 0, 1, and 2, arranged in-place in the order 0, 1, 2.

 

Constraints:

  • n == nums.length
  • 1 <= n <= 300
  • nums[i] is either 0, 1, or 2.

 

Follow up: Could you come up with a one-pass algorithm using only constant extra space?

TL;DR — 30s scan

  • Naive way: compare every pair or scan many times, which can take quadratic time and repeats work.
  • Gold way: keep three sections (0s, unknown, 2s) and move each element to its section in one linear pass.
  • Switch to the gold method when the input has only a few fixed values and you need O(n) time with constant extra space.
Spot next time: If you must reorder an array that contains only a small set of distinct numbers and you are required to do it in one pass without extra storage, think about growing sorted zones from the ends and swapping elements into their correct zone.

  • Naive approaches like bubble or insertion sort run in O(n²) time, wasting effort on sorted data.

Complexity: O(n) time, O(1) extra space
def sortColors(nums):
    low, mid, high = (0, 0, len(nums) - 1)
    while mid <= high:
        if nums[mid] == 0:
            nums[low], nums[mid] = (nums[mid], nums[low])
            low += 1
            mid += 1
        elif nums[mid] == 1:
            mid += 1
        else:
            nums[mid], nums[high] = (nums[high], nums[mid])
            high -= 1
Takeaway
Use three-way partitioning for linear time instead of slower generic sorts.
Three-zone two pointers
Keep three parts of the array: 0s on the left, unknown in the middle, 2s on the right. Scan the unknown part once; 0 gets swapped left, 2 gets swapped right, 1 just stays in the middle.
Why it fits (4) — properties
  • Only 3 possible values: 0, 1, 2.
  • Required order is fixed: 0s, then 1s, then 2s.
  • Swapping with the left/right edge safely grows sorted zones.
  • Follow-up asks one pass and constant extra space.
Spot it (3)
  • Only a few fixed values/colors, with required order.
  • Need in-place, often one pass.
  • Each item can be pushed left, kept middle, or pushed right.
How you'd derive it (first principles)
  1. Imagine scanning and seeing a 0. It belongs before everything else, so you want to push it left.
  2. Seeing a 2 means it belongs after everything else, so push it right.
  3. Then you realize 1s can just wait in the middle, so you only need boundaries for the left and right zones.
Plan (4 steps)
  1. Set left, right, and scan pointers.
  2. Loop while scan is inside unknown.
  3. Check the current value.
  4. Swap 0 left, swap 2 right, move past 1.
Start when stuck: Draw the array as [0-zone][unknown][2-zone]. · Use one pointer for the left edge, one for the right edge, and one to scan unknown.
left = 0
right = len(nums) - 1
i = 0
while i <= right:
    if nums[i] == 0:
        nums[left], nums[i] = (nums[i], nums[left])
        left += 1
        i += 1
    elif nums[i] == 2:
        nums[right], nums[i] = (nums[i], nums[right])
        right -= 1
    else:
        i += 1
Complexity: O(n) time, O(1) extra space.

✅ Quick check

Q1: What goes wrong if you advance the scan pointer after swapping a 2 to the right but forget to check the new value that landed at the scan position?
Hint: After a swap, the element you bring in from the right side has not been examined yet.
You might skip a value that still needs to be moved, leaving a 2 in the middle or a 0 on the right side, breaking the final order.
Q2: Why can we simply move the scan pointer forward when we see a 1, without any swapping?
Hint: Think about what the three sections represent and where a 1 fits.
Because a 1 belongs in the middle section, between the 0s on the left and the 2s on the right, so it is already in the correct zone.

Checklist

If you need to sort only 0, 1, 2 in-place in one pass, keep left/middle/right zones and swap edge values into their zone.
