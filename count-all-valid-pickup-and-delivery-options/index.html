Count All Valid Pickup and Delivery Options

Hard Math, Dynamic Programming, Combinatorics
LeetCode →

Problem

Show full problem ↕

Given n orders, each order consists of a pickup and a delivery service.

Count all valid pickup/delivery possible sequences such that delivery(i) is always after of pickup(i). 

Since the answer may be too large, return it modulo 10^9 + 7.

 

Example 1:

Input: n = 1
Output: 1
Explanation: Unique order (P1, D1), Delivery 1 always is after of Pickup 1.

Example 2:

Input: n = 2
Output: 6
Explanation: All possible orders: 
(P1,P2,D1,D2), (P1,P2,D2,D1), (P1,D1,P2,D2), (P2,P1,D1,D2), (P2,P1,D2,D1) and (P2,D2,P1,D1).
This is an invalid order (P1,D2,P2,D1) because Pickup 2 is after of Delivery 2.

Example 3:

Input: n = 3
Output: 90

 

Constraints:

  • 1 <= n <= 500

TL;DR — 30s scan

  • The naive method tries every possible order of pickups and deliveries by building sequences step by step, which is very slow for large n.
  • The gold method builds the sequence one order at a time, counting the ways to insert a new pickup and delivery without breaking the rule that pickup comes before delivery.
  • Switch to the gold method when n is large (like 500) because the naive method becomes too slow, but the gold method runs in a simple loop.
Spot next time: When you have to arrange pairs of events where one must come before the other, and you need to count all valid orders, think about adding one pair at a time and multiplying the choices.

Backtracking / brute-force valid sequences — 2n labeled events; next slot can be any unused pickup or any open delivery.
  • n = 500 -> 1000 events; valid sequences = (2n)! / 2^n.
  • Same (picked, delivered) masks recur; memo still leaves 3^n states.
Complexity: O(n^2 * (2n)! / 2^n) time, O(n) stack; memo O(n * 3^n) time, O(3^n) space.
MOD = 10 ** 9 + 7

def count_orders_naive(n):
    full = (1 << n) - 1

    def dfs(picked, done):
        if done == full:
            return 1
        total = sum((dfs(picked | bit, done) for bit in (1 << i for i in range(n)) if not picked & bit))
        total += sum((dfs(picked, done | bit) for bit in (1 << i for i in range(n)) if picked & bit and (not done & bit)))
        return total % MOD
    return dfs(0, 0)
Takeaway
Ditch when only counts matter; use dp[0] = 1, dp[i] = dp[i - 1] * i * (2 * i - 1) mod MOD.
Add one pair at a time
Start with a valid sequence for fewer orders, then add the next pickup/delivery pair. The old sequence stays valid, so you only need to count where P and D can go while keeping P before D.
Why it fits (4) — properties
  • Each order has exactly one pickup and one delivery.
  • The only rule is Pi before Di; other orders do not block it.
  • Adding a new order never breaks old valid orders.
  • n is up to 500, so a loop is enough and enumeration is impossible.
Spot it (3)
  • Counting valid sequences with paired before-after rules.
  • Each item has two related events, like pickup then delivery.
  • The answer is huge, so use modulo and recurrence instead of listing all orders.
How you'd derive it (first principles)
  1. Imagine n = 1: only P1, D1 works.
  2. Add P2 and D2 into that old sequence; P2 must come before D2.
  3. You will see 6 possible placements, so dp[2] = 1 * 6.
Plan (4 steps)
  1. Keep dp as the count for already built orders.
  2. Loop i from 2 to n.
  3. Count ways to place Pi before Di: i * (2 * i - 1).
  4. Update dp = dp * ways % MOD.
Start when stuck: Draw the n = 2 case by inserting P2/D2 into P1/D1. · Count placements for one new pair, then ask if the same count works for every next order.
MOD = 10 ** 9 + 7

def countOrders(n: int) -> int:
    dp = 1
    for i in range(2, n + 1):
        ways = i * (2 * i - 1)
        dp = dp * ways % MOD
    return dp
Complexity: Time: O(n). Space: O(1).

✅ Quick check

Q1: Why does adding a new order pair (pickup and delivery) to an existing valid sequence multiply the number of total sequences by i*(2i-1)? What would happen if the rule that pickup must come before delivery was removed?
Hint: Think about the number of gaps before and after the pickup.
When adding the i-th order, there are 2i-1 gaps in the existing sequence. The pickup can go in any of these gaps. Then the delivery must go in a gap after the pickup. The total number of valid placements for the i-th order is i*(2i-1). If the rule was removed, then the pickup and delivery could be placed in any two gaps and in any order, so the number of ways would be (2i-1)*(2i), which is twice as much because now both orders (pickup then delivery and delivery then pickup) are allowed.
Q2: The gold method starts with one order and then adds orders one by one. Why does this work without missing any valid sequences? What property of the problem ensures that every valid sequence can be built this way?
Hint: Think about the last order added and how it must fit into the existing sequence.
Every valid sequence for n orders can be built by starting with a valid sequence for n-1 orders and then inserting the nth pickup and delivery in a way that the pickup comes before the delivery. This works because the relative order of the first n-1 orders doesn't change, and the nth order is added without breaking the rule. So the set of valid sequences for n orders is exactly the set of sequences that can be built by extending a valid sequence for n-1 orders.

Checklist

If you must count valid pickup-delivery orders with each delivery after its own pickup, build one order pair at a time and multiply the new placement choices.
