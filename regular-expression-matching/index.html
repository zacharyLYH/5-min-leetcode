Given an input string s and a pattern p, implement regular expression matching with support for '.' and '*' where:

  • '.' Matches any single character.​​​​
  • '*' Matches zero or more of the preceding element.

Return a boolean indicating whether the matching covers the entire input string (not partial).

 

Example 1:

Input: s = "aa", p = "a"
Output: false
Explanation: "a" does not match the entire string "aa".

Example 2:

Input: s = "aa", p = "a*"
Output: true
Explanation: '*' means zero or more of the preceding element, 'a'. Therefore, by repeating 'a' once, it becomes "aa".

Example 3:

Input: s = "ab", p = ".*"
Output: true
Explanation: ".*" means "zero or more (*) of any character (.)".

 

Constraints:

  • 1 <= s.length <= 20
  • 1 <= p.length <= 20
  • s contains only lowercase English letters.
  • p contains only lowercase English letters, '.', and '*'.
  • It is guaranteed for each appearance of the character '*', there will be a previous valid character to match.

def isMatch(s, p):
    if not p:
        return not s
    first = bool(s) and p[0] in {s[0], '.'}
    if len(p) > 1 and p[1] == '*':
        return isMatch(s, p[2:]) or (first and isMatch(s[1:], p))
    return first and isMatch(s[1:], p[1:])

Dynamic Programming
Build the answer from smaller answers: whether the first i characters of s match the first j characters of p. Store each small answer in a table and reuse it instead of retesting the same remaining pair.
Why it fits (3) — properties
  • A local match determines the next smaller question, so the whole string can be checked left to right.
  • A '*' creates explicit options: skip the repeated element or consume one matching copy.
  • Different match paths reach the same smaller remaining pairs, so each pair needs one stored answer.
Spot it (3)
  • You must match the entire input, not find a substring.
  • The pattern uses '.', and '*' repeats the immediately preceding element.
  • The alphabet and lengths are small, but many paths ask the same smaller questions.
How you'd derive it (first principles)
  1. Imagine comparing from the front. If a character matches, consume it; if '*' follows, try skipping that group or consuming one matching copy.
  2. Notice both choices ask for the same kind of answer on a shorter pair.
  3. Record each answer once, starting with both strings empty.
Plan (4 steps)
  1. Make a table whose rows count used s characters and whose columns count used p characters.
  2. Seed the empty-empty cell as true.
  3. For every other cell, check a direct character match or a '*' repeat.
  4. Return the cell covering all of s and p.
Start when stuck: Mark empty s with empty p as true; mark empty p with nonempty s as false. · For each pattern position, separate the '*' case from the one-character case.
dp = [True, False]
for _ in range(len(s)):
    if p:
        first = p[0] == s[0] or p[0] == '.'
        star = len(p) >= 2 and p[1] == '*'
        if star:
            dp = dp[1:] or (first and dp[0])
        else:
            dp = first and dp[0]
        s = s[1:]
        p = p[2:] if star else p[1:]
return bool(dp)
Complexity: Time O(n * m), space O(m).

✅ Quick check

Q1: In the table-based method, why do you need to look at two different choices whenever you encounter a star (*) in the pattern?
Hint: Imagine you have a choice: stop now, or eat one bite of cake. To know which is better, you have to figure out what comes next after both decisions.
A star means you can either delete that part of the pattern or use one copy of the item before it. Both choices leave you with a new, smaller problem that you must compare.
Q2: What simple idea lets the dynamic programming table turn an impossible 'what-if' scenario into a fast calculation?
Hint: Think of it like a notebook where you write down 'Yes, these parts match' or 'No, they don't'. If you face the same situation later, you just flip open that page.
By recording the result of every possible small match in a list (table) before moving on, you never have to guess the same small thing twice.
