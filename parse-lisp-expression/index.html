Parse Lisp Expression

Hard Hash Table, String, Stack, Recursion
LeetCode →

Problem

You are given a string expression representing a Lisp-like expression to return the integer value of.

The syntax for these expressions is given as follows.

  • An expression is either an integer, let expression, add expression, mult expression, or an assigned variable. Expressions always evaluate to a single integer.
  • (An integer could be positive or negative.)
  • A let expression takes the form "(let v1 e1 v2 e2 ... vn en expr)", where let is always the string "let", then there are one or more pairs of alternating variables and expressions, meaning that the first variable v1 is assigned the value of the expression e1, the second variable v2 is assigned the value of the expression e2, and so on sequentially; and then the value of this let expression is the value of the expression expr.
  • An add expression takes the form "(add e1 e2)" where add is always the string "add", there are always two expressions e1, e2 and the result is the addition of the evaluation of e1 and the evaluation of e2.
  • A mult expression takes the form "(mult e1 e2)" where mult is always the string "mult", there are always two expressions e1, e2 and the result is the multiplication of the evaluation of e1 and the evaluation of e2.
  • For this question, we will use a smaller subset of variable names. A variable starts with a lowercase letter, then zero or more lowercase letters or digits. Additionally, for your convenience, the names "add", "let", and "mult" are protected and will never be used as variable names.
  • Finally, there is the concept of scope. When an expression of a variable name is evaluated, within the context of that evaluation, the innermost scope (in terms of parentheses) is checked first for the value of that variable, and then outer scopes are checked sequentially. It is guaranteed that every expression is legal. Please see the examples for more details on the scope.

 

Example 1:

Input: expression = "(let x 2 (mult x (let x 3 y 4 (add x y))))"
Output: 14
Explanation: In the expression (add x y), when checking for the value of the variable x,
we check from the innermost scope to the outermost in the context of the variable we are trying to evaluate.
Since x = 3 is found first, the value of x is 3.

Example 2:

Input: expression = "(let x 3 x 2 x)"
Output: 2
Explanation: Assignment in let statements is processed sequentially.

Example 3:

Input: expression = "(let x 1 y 2 x (add x y) (add x y))"
Output: 5
Explanation: The first (add x y) evaluates as 3, and is assigned to x.
The second (add x y) evaluates as 3+2 = 5.

 

Constraints:

  • 1 <= expression.length <= 2000
  • There are no leading or trailing spaces in expression.
  • All tokens are separated by a single space in expression.
  • The answer and all intermediate calculations of that answer are guaranteed to fit in a 32-bit integer.
  • The expression is guaranteed to be legal and evaluate to an integer.

Why it fits (3)
  • Nested parentheses require depth‑first evaluation of sub‑expressions
  • Variable shadowing demands innermost‑first lookup
  • let introduces sequential bindings before the final expression
Spot it (3)
  • Expression contains '(' and ')' with keywords let/add/mult
  • Tokens are separated by a single space, making split trivial
  • Need to respect sequential assignment and scoping rules
From first principles
  1. Tokenize the string; each '(' starts a new subexpression that must be fully evaluated before continuing
  2. When encountering let, push a new scope, bind each variable to the value of its following expression in order, then evaluate the final expr
  3. For variable lookup, search scopes from most recent to oldest; integers are parsed directly
Plan (8 steps)
  1. Tokenize via expression.split()
  2. Define helper lookup(var, env_stack) that scans env_stack reversed
  3. In eval, if token is '(' then peek next token to decide operator
  4. For let: create new dict, push onto env_stack, loop reading var‑expr pairs until the next token is not a variable (i.e., '(' or a number or protected keyword), evaluate each expr, assign, then evaluate final expr
  5. For add/mult: evaluate two subexpressions, compute sum/product
  6. For token that is not '(': if it's a number (maybe with leading '-') return its int, else treat as variable and lookup
  7. After evaluating a subexpression, if current token is ')', pop the scope if we entered a let, increment index and return value
  8. Kick off eval from index 0 with an empty env stack and return the obtained value
Start: Split expression by spaces to get tokens and keep an index pointer that advances as we parse · Write a recursive function eval(idx, env) that returns (value, next_index) and handles '(' , integers, and variables
Complexity: O(n) time, O(n) space
def evaluate(expression: str) -> int:/n    tokens = expression.split()/n    n = len(tokens)/n    /n    def lookup(var, env):/n        for frame in reversed(env):/n            if var in frame:/n                return frame[var]/n        raise ValueError('Undefined variable {}'.format(var))/n    /n    def eval_at(i, env):/n        if tokens[i] == '(':/n            op = tokens[i + 1]/n            if op == 'let':/n                env.append({})/n                j = i + 2/n                while j < n and tokens[j] not in ('(', ')', 'add', 'mult', 'let') and tokens[j][0].islower():/n                    var = tokens[j]/n                    val, j = eval_at(j + 1, env)/n                    env[-1][var] = val/n                    j += 1/n                result, j = eval_at(j, env)/n                env.pop()/n                return result, j + 1/n            elif op == 'add' or op == 'mult':/n                a, j = eval_at(i + 2, env)/n                b, j = eval_at(j, env)/n                res = a + b if op == 'add' else a * b/n                return res, j + 1/n            else:/n                raise ValueError('Unknown operator {}'.format(op))/n        else:/n            tok = tokens[i]/n            if tok[0] == '-' or tok[0].isdigit():/n                return int(tok), i + 1/n            else:/n                return lookup(tok, env), i + 1/n    /n    value, _ = eval_at(0, []))/n    return value
def evaluate(expr):
    tokens = expr.split()
    def parse(i):
        if tokens[i] != '(':
            return int(tokens[i]), i+1
        op = tokens[i+1]
        return 0, i
    return parse(0)[0]

✅ Quick check

Q1: Why does pushing a new scope for each let and popping it after evaluating the final expression guarantee correct variable shadowing?
Hint: Consider the lifetime of a binding versus the lifetime of the sub‑expression that uses it.
Inner bindings hide outer ones and are discarded when the let ends, so lookups only see the innermost active value.
Q2: What would break if we evaluated all let bindings before any of them, instead of sequentially?
Hint: Think about a let where the second variable’s expression uses the first variable.
Later bindings could not refer to earlier ones, breaking the sequential assignment semantics of let.
