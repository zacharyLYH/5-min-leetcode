N-Repeated Element in Size 2N Array

Easy Array, Hash Table, Pigeonhole Principle

You are given an integer array nums with the following properties:

  • nums.length == 2 * n.
  • nums contains n + 1 unique values, n of which occur exactly once in the array.
  • Exactly one element of nums is repeated n times.

Return the element that is repeated n times.

 

Example 1:

Input: nums = [1,2,3,3]
Output: 3

Example 2:

Input: nums = [2,1,2,5,3,2]
Output: 2

Example 3:

Input: nums = [5,1,5,2,5,3,5,4]
Output: 5

 

Constraints:

  • 2 <= n <= 5000
  • nums.length == 2 * n
  • 0 <= nums[i] <= 104
  • nums contains n + 1 unique elements and one of them is repeated exactly n times.

TL;DR — 30s scan

  • The naïve method compares every possible pair of elements, which costs about n squared operations and becomes extremely slow as n grows.
  • The gold method walks through the list once, only ever looking at an element and its immediate neighbour (or the neighbour after that). Because the repeated value fills half the array, at least two copies must be close enough, so the shortcut runs in linear time.
Spot next time: If you notice the array length is exactly twice some integer n and one value occurs n times while every other value is unique, then the repeated number must appear next to another copy within two positions, so a quick neighbour check will find it.

Window size 3 → duplicate appears twice

Brute‑force pair scan — Count each value by comparing it to every other element
  • Quadratic work: ~ (2n)² comparisons → up to 10⁸ ops for max input
  • Redundant checks: same pair examined many times before the n‑th hit
Complexity: O(n²)
def findRepeated(nums):
    n = len(nums) // 2
    for i in range(len(nums)):
        cnt = 0
        for j in range(len(nums)):
            if nums[i] == nums[j]:
                cnt += 1
                if cnt == n:
                    return nums[i]
Takeaway
Drop this method when n grows beyond a few hundred; use a hash set or pigeonhole principle instead.
Local duplicate check (pigeonhole window)
If you look at a small group of positions, the element that appears many times must show up twice inside that group. So you just scan the array and compare each element with the next one or the one after that; the first match you find is the answer.
Why it fits (2) — properties
  • Array length is 2n, one value occurs n times (half the array), all other values occur once.
  • Because the repeated element fills half the slots, any two positions that are at most two apart cannot all be distinct; a duplicate must appear in some nearby pair.
Spot it (3)
  • Length is even and exactly half the array is the same number
  • All other numbers appear only once
  • Need to find the element that occurs more than once; checking adjacent or distance‑2 pairs is enough
How you'd derive it (first principles)
  1. Imagine you spread the repeated number as far apart as possible; to keep it from touching itself you would need to put a different number between each copy, but there are only n other distinct numbers, so eventually two copies end up next to each other or with just one number between them.
  2. Therefore scanning for a match at distance 1 or 2 will catch it.
Plan (4 steps)
  1. Loop i from 0 to len(nums)-2
  2. If nums[i]==nums[i+1], return nums[i]
  3. If i+2 < len(nums) and nums[i]==nums[i+2], return nums[i]
  4. The loop will always return before finishing.
Start when stuck: If you see no immediate duplicate, start checking each element against the one right after it. · If that fails, check against the element two steps ahead.
def repeatedNTimes(nums):
    n = len(nums)
    for i in range(n - 1):
        if nums[i] == nums[i + 1]:
            return nums[i]
        if i + 2 < n and nums[i] == nums[i + 2]:
            return nums[i]
Complexity: O(n) time, O(1) space

✅ Quick check

Q1: Why can we limit our search to an element and its immediate neighbour (or the neighbour after that) to guarantee finding the repeated number?
Hint: Imagine trying to place the repeated number as far away from itself as possible while using all the other numbers only once—you’ll run out of room, forcing a close pair.
Because the repeated value occupies half the array; spreading it far apart requires more distinct filler numbers than exist, so somewhere two copies become neighbours or separated by only one slot.
Q2: What would go wrong if the repeated value occurred fewer than n times (i.e., not half the array) and we still tried the neighbour‑only scan?
Hint: Picture spreading the repeated value across the whole array with gaps larger than two; the algorithm would then have no chance to see a matching pair.
It could miss the duplicate. With fewer repetitions you could arrange them far apart, leaving no two copies within two positions, so the fast method would fail.

Checklist

If you need to find the element that appears half the time in an array where every other value is unique, look for a match in nearby positions.
