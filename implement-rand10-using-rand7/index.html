Implement Rand10() Using Rand7()

Given the API rand7() that generates a uniform random integer in the range [1, 7], write a function rand10() that generates a uniform random integer in the range [1, 10]. You can only call the API rand7(), and you shouldn't call any other API. Please do not use a language's built-in random API.

Each test case will have one internal argument n, the number of times that your implemented function rand10() will be called while testing. Note that this is not an argument passed to rand10().

 

Example 1:

Input: n = 1
Output: [2]

Example 2:

Input: n = 2
Output: [2,8]

Example 3:

Input: n = 3
Output: [3,8,10]

 

Constraints:

  • 1 <= n <= 105

 

Follow up:

  • What is the expected value for the number of calls to rand7() function?
  • Could you minimize the number of calls to rand7()?

Rejection Sampling: accept 1‑40 → 1‑10

Rejection sampling — Two rand7 calls give 49 equiprobable outcomes.
  • 9/49 outcomes rejected → possible retries.
  • Each rand10 may loop many times → hurts large n.
Complexity: Expected O(1) per call, worst‑case unbounded; naïve count looks O(n^2).
def rand10():
    while True:
        a = rand7()
        b = rand7()
        num = (a - 1) * 7 + b
        if num <= 40:
            return 1 + (num - 1) % 10
Takeaway
Drop the plain loop and recycle rejected entropy to cut calls.
Rejection Sampling
When you only have a uniform random generator for a small range, you can combine several calls to create a larger uniform sample space. Then you keep only the outcomes that map evenly to your desired range, discarding the rest and trying again, which guarantees uniformity.
Why it fits (2) — properties
  • The source generator is uniform and each call is independent, so combinations produce a uniform distribution over the product space.
  • The target range must evenly divide a subset of that product space for rejection to preserve uniformity.
Spot it (3)
  • Need to generate a uniform random integer in a range that is not a multiple of the source range
  • Only have a uniform generator with a smaller range
  • Can call the source multiple times to expand the sample space
How you'd derive it (first principles)
  1. Imagine you have a 7-sided die and you need a fair 10-sided result.
  2. Rolling twice gives 49 equally likely pairs, but 49 isn't a multiple of 10, so a direct mapping would bias some numbers.
  3. Instead, accept only the first 40 pairs (which is a multiple of 10), map them to 1-10, and reject the remaining 9 pairs, rolling again if you get one of them.
Plan (4 steps)
  1. Call rand7() twice to obtain two numbers a and b.
  2. Compute a combined value in a uniform space, e.g., (a-1)*7 + b giving 1..49.
  3. If the combined value is within an accepted range that is a multiple of 10 (e.g., <=40), return (value-1)%10 + 1.
  4. Otherwise reject and repeat the process.
Start when stuck: If you're stuck, think about combining two rolls to create a larger range. · Then consider discarding any result that doesn't fit an even multiple of your target range.
def rand10():
    while True:
        a = rand7()
        b = rand7()
        num = (a - 1) * 7 + b
        if num <= 40:
            return (num - 1) % 10 + 1
Complexity: O(1) expected per call, O(n) total for n calls

✅ Quick check

Q1: Why did we stop counting after the number 40?
Hint: Think of filling boxes with balls. If you have 49 balls and 10 slots per box, you will have 9 empty spaces at the last box. Those empty spaces are the leftovers we must throw away.
Because 49 total pairs (from two 7‑sided rolls) cannot be divided evenly into groups of 10. Stopping at 40 removes the leftover pairs, ensuring every number 1‑10 appears the same number of times.
Q2: What keeps the whole process fair if we lose some pairs during rejection?
Hint: If you cut a rope into lengths that don't divide evenly, the ends won't align. You must cut off the unused scraps.
We only keep pairs that fit perfectly into groups of ten. As long as the kept set has a complete number of groups, every outcome stays equally likely.

Checklist

If you need to generate a uniform random number in a range that is not a multiple of the source, combine multiple source calls to expand the range and reject outcomes that don't divide evenly.
