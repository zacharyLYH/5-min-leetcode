Earliest Finish Time for Land and Water Rides I

Easy Array, Two Pointers, Binary Search, Greedy, Sorting

You are given two categories of theme park attractions: land rides and water rides.

  • Land rides
    • landStartTime[i] – the earliest time the ith land ride can be boarded.
    • landDuration[i] – how long the ith land ride lasts.
  • Water rides
    • waterStartTime[j] – the earliest time the jth water ride can be boarded.
    • waterDuration[j] – how long the jth water ride lasts.

A tourist must experience exactly one ride from each category, in either order.

  • A ride may be started at its opening time or any later moment.
  • If a ride is started at time t, it finishes at time t + duration.
  • Immediately after finishing one ride the tourist may board the other (if it is already open) or wait until it opens.

Return the earliest possible time at which the tourist can finish both rides.

 

Example 1:

Input: landStartTime = [2,8], landDuration = [4,1], waterStartTime = [6], waterDuration = [3]

Output: 9

Explanation:​​​​​​​

  • Plan A (land ride 0 → water ride 0):
    • Start land ride 0 at time landStartTime[0] = 2. Finish at 2 + landDuration[0] = 6.
    • Water ride 0 opens at time waterStartTime[0] = 6. Start immediately at 6, finish at 6 + waterDuration[0] = 9.
  • Plan B (water ride 0 → land ride 1):
    • Start water ride 0 at time waterStartTime[0] = 6. Finish at 6 + waterDuration[0] = 9.
    • Land ride 1 opens at landStartTime[1] = 8. Start at time 9, finish at 9 + landDuration[1] = 10.
  • Plan C (land ride 1 → water ride 0):
    • Start land ride 1 at time landStartTime[1] = 8. Finish at 8 + landDuration[1] = 9.
    • Water ride 0 opened at waterStartTime[0] = 6. Start at time 9, finish at 9 + waterDuration[0] = 12.
  • Plan D (water ride 0 → land ride 0):
    • Start water ride 0 at time waterStartTime[0] = 6. Finish at 6 + waterDuration[0] = 9.
    • Land ride 0 opened at landStartTime[0] = 2. Start at time 9, finish at 9 + landDuration[0] = 13.

Plan A gives the earliest finish time of 9.

Example 2:

Input: landStartTime = [5], landDuration = [3], waterStartTime = [1], waterDuration = [10]

Output: 14

Explanation:​​​​​​​

  • Plan A (water ride 0 → land ride 0):
    • Start water ride 0 at time waterStartTime[0] = 1. Finish at 1 + waterDuration[0] = 11.
    • Land ride 0 opened at landStartTime[0] = 5. Start immediately at 11 and finish at 11 + landDuration[0] = 14.
  • Plan B (land ride 0 → water ride 0):
    • Start land ride 0 at time landStartTime[0] = 5. Finish at 5 + landDuration[0] = 8.
    • Water ride 0 opened at waterStartTime[0] = 1. Start immediately at 8 and finish at 8 + waterDuration[0] = 18.

Plan A provides the earliest finish time of 14.​​​​​​​

 

Constraints:

  • 1 <= n, m <= 100
  • landStartTime.length == landDuration.length == n
  • waterStartTime.length == waterDuration.length == m
  • 1 <= landStartTime[i], landDuration[i], waterStartTime[j], waterDuration[j] <= 1000

Brute force pair enumeration — Try every land ride then every water ride (or vice versa) and compute finish time
  • n,m up to 100 => 10^4 combos, but naive double loop over all pairs for each order yields O(n*m) which is fine, but if we also consider ordering we might double work
  • Repeatedly recomputes max(start_time, finish_time) for each pair without early pruning
Complexity: O(n*m) time, O(1) extra space
def earliestFinishTime(landStart, landDur, waterStart, waterDur):
    best = float('inf')
    for i in range(len(landStart)):
        for j in range(len(waterStart)):
            # land then water
            t = landStart[i] + landDur[i]
            t = max(t, waterStart[j]) + waterDur[j]
            best = min(best, t)
            # water then land
            t = waterStart[j] + waterDur[j]
            t = max(t, landStart[i]) + landDur[i]
            best = min(best, t)
    return best
Takeaway
When constraints are tiny, brute force is acceptable; avoid if input size grows
Sort + Prefix/Suffix Min + Binary Search
First, notice that delaying a ride never helps, so each ride starts at its earliest opening time. This turns the finish time for a pair into a simple formula that depends only on the ride’s finish time and the other ride’s start time and duration. After sorting one list by start time, we can pre‑compute the best duration for all rides that start before a given point (prefix min) and the best (start+duration) for rides that start after (suffix min). Then for each possible finish time we binary‑search the split point and combine the two minima in O(log n).
Why it fits (3) — properties
  • The finish time expression splits into two cases based on whether the other ride’s start time is ≤ or > the current ride’s finish time.
  • Both cases become monotonic after sorting by start time, allowing prefix/suffix minima.
  • Constraints are small but the pattern gives O((n+m) log (n+m)) instead of brute O(nm).
Spot it (3)
  • Need to minimize over pairs a formula involving max(start1+dur1, start2) + dur2 (or symmetric).
  • Start times and durations are independent positive integers ≤ 1000.
  • Sorting one list lets us answer “best partner” queries with a binary search.
How you'd derive it (first principles)
  1. Imagine you realize waiting to start a ride only makes you finish later, so you always start each ride at its earliest opening.
  2. Then the total time for land→water is max(landFinish, waterStart) + waterDur, which is either landFinish+waterDur (if water opens early) or waterStart+waterDur (if water opens later).
  3. Now you see you need the minimum over all water rides of either a constant plus waterDur (for early opens) or waterStart+waterDur (for late opens); sorting lets you get the minimum of each group with a prefix min of durations and a suffix min of start+duration.
  4. Do the same for water→land and take the overall minimum.
Plan (5 steps)
  1. Compute arrays landFinish = landStart+landDuration and waterFinish = waterStart+waterDuration.
  2. Sort water rides by start time; build prefix min of waterDuration and suffix min of (start+duration).
  3. For each landFinish, binary‑search the split in the sorted water starts and combine the two minima to get the best land→water time.
  4. Repeat the same process swapping land and water to get the best water→land time.
  5. Return the smallest of the two results.
Start when stuck: If stuck, write the O(nm) brute force to confirm the formula. · Then sort one list and think about how to answer “what’s the best water ride for a given land finish?” in sub‑linear time.
def best(finish, starts, pref_min_dur, suff_min_sd):  # core loop ≤12 lines  n    import bisect  n    ans = float('inf')  n    for f in finish:  n        i = bisect.bisect_right(starts, f)  n        if i:  n            ans = min(ans, f + pref_min_dur[i-1])  n        if i < len(starts):  n            ans = min(ans, suff_min_sd[i])  n    return ans
Complexity: O((n+m) log (n+m))

✅ Quick check

Q1: Why does sorting the partner rides by start time let us replace the inner loop with a prefix min of durations and a suffix min of (start+duration)?
Hint: Think about what the max(...) becomes in each region and how that isolates a term that depends only on the partner ride.
After sorting, all rides with start ≤ current finish form a prefix where the extra wait is zero, so total = finish + duration; the minimum duration in that prefix gives the best case. Rides with start > finish form a suffix where wait = start‑finish, so total = start+duration; the minimum start+duration in that suffix gives the best case.
Q2: What would break the prefix/suffix trick if we could not assume each ride starts at its earliest opening time?
Hint: Consider whether the expression max(start+dur, otherStart) + otherDur still separates into two independent parts when start is variable.
If we could delay a ride, the finish time would no longer be a simple function of start+duration; the wait term could depend on chosen delay, destroying the monotonic split needed for prefix/suffix minima.
