Given an integer array arr, return the number of distinct bitwise ORs of all the non-empty subarrays of arr.

The bitwise OR of a subarray is the bitwise OR of each integer in the subarray. The bitwise OR of a subarray of one integer is that integer.

A subarray is a contiguous non-empty sequence of elements within an array.

 

Example 1:

Input: arr = [0]
Output: 1
Explanation: There is only one possible result: 0.

Example 2:

Input: arr = [1,1,2]
Output: 3
Explanation: The possible subarrays are [1], [1], [2], [1, 1], [1, 2], [1, 1, 2].
These yield the results 1, 1, 2, 1, 3, 3.
There are 3 unique values, so the answer is 3.

Example 3:

Input: arr = [1,2,4]
Output: 6
Explanation: The possible results are 1, 2, 3, 4, 6, and 7.

 

Constraints:

  • 1 <= arr.length <= 5 * 104
  • 0 <= arr[i] <= 109

TL;DR — 30s scan

  • Naive way: look at every possible subarray, compute its OR from scratch – this grows quadratically and becomes too slow for big arrays.
  • Gold way: while scanning left to right, keep only the OR results of subarrays that end at the current spot; because OR only gains bits, the list stays tiny (at most the number of bits in an integer).
  • Switch to the gold way when the array length is more than a few hundred or when you notice the operation only adds information and never removes it.
Spot next time: When you need distinct results of an operation that only adds bits (or only increases) over all contiguous pieces, think of keeping the set of results for pieces that end at each index and update it with the new element.

Brute‑force enumeration of all subarrays — Iterate over every start index and extend the subarray, accumulating OR values.
  • Number of subarrays is O(n²) → cannot precompute efficiently for n=5·10⁴.
  • Recomputing OR from scratch for overlapping ranges wastes work.
Complexity: O(n²) time, O(1) extra space
def countDistinctORs(arr):
    results = set()
    n = len(arr)
    for i in range(n):
        cur = 0
        for j in range(i, n):
            cur |= arr[j]
            results.add(cur)
    return len(results)
Takeaway
When n grows beyond a few hundred, abandon full enumeration and use DP or bit‑mask tricks.
Rolling OR set for subarrays ending at each position
As we scan the array left to right, we keep all distinct OR values of subarrays that end at the current index. When we move to the next element, each previous OR can only gain bits (OR never removes bits), so the new set is just the old ORed with the new element plus the element itself. This lets us update in O(number of bits) time instead of recomputing every subarray.
Why it fits (3) — properties
  • Bitwise OR is monotonic: adding more numbers can only set more bits, never unset them.
  • Because integers are ≤1e9 (≤30 bits), any OR value can change at most 30 times while we extend a subarray.
  • Thus the set of ORs for subarrays ending at a position stays small (≤32).
Spot it (3)
  • We need distinct results of a bitwise operation over all contiguous subarrays.
  • The operation only adds bits (OR) and never removes them.
  • Input size up to 5·10⁴, values fit in 32‑bit integers.
How you'd derive it (first principles)
  1. Imagine you fix a start index and extend the subarray to the right; the OR value only changes when a new bit appears.
  2. After at most 30 changes the value stops changing, so long stretches produce the same OR.
  3. Therefore, for each ending position we only need to remember the few OR values that actually changed.
Plan (8 steps)
  1. Initialize an empty set `all_results` for the final answer.
  2. Initialize an empty set `cur` for ORs of subarrays ending at the previous index.
  3. Iterate through each number `x` in the array:
  4. Build a new set `nxt` containing `x` itself.
  5. For each value `v` in `cur`, add `v | x` to `nxt`.
  6. Replace `cur` with `nxt`.
  7. Add every value in `cur` to `all_results`.
  8. Return the size of `all_results`.

✅ Quick check

Q1: If the operation could both set and unset bits as we extend a subarray, why would keeping only the ORs of subarrays ending at each position no longer stay small?
Hint: Think about what happens when a new element can both turn a bit on and turn it off – how many different values could appear as you keep extending?
Because the value could go up and down many times, so you might need to remember many different results for the same ending point, breaking the small‑set guarantee.
Q2: Why does the fact that each integer has at most 30 bits guarantee that the set of ORs for subarrays ending at a position never exceeds about 32 elements?
Hint: Count how many times a bit can flip from 0 to 1 while you keep adding numbers to the right.
Each time the OR value changes, at least one new bit becomes set; since there are only 30 bits to set, after at most 30 changes the value stops changing, so only a handful of distinct values can appear.

Checklist

If you need to count distinct results of a monotonic bitwise operation over all subarrays, keep the set of results for subarrays ending at each position and update it with the current element.
